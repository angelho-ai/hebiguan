# Google Sheet 表單串接（約 5 分鐘）

## 步驟

1. 開一個新的 Google 試算表：<https://sheets.new>，命名例如「何必館看屋預約」。
2. 上方選單 **擴充功能 → Apps Script**。
3. 刪掉編輯器裡的預設內容，把本資料夾 `Code.gs` 的全部內容貼上，**儲存**（Ctrl/Cmd+S）。
   - 通知信預設寄到 `angel.ho.ai.pm@gmail.com`，要改或關閉請改檔案最上方的 `NOTIFY_EMAIL`。
4. 右上角 **部署 → 新增部署作業**：
   - 類型選 **網頁應用程式**
   - 執行身分：**我**
   - 誰可以存取：**所有人**（一定要選這個，表單才送得進來）
   - 按「部署」，第一次會要求授權 → 選你的帳號 → 進階 → 前往（不安全）→ 允許。
5. 複製部署完成後給的 **網頁應用程式網址**（`https://script.google.com/macros/s/xxxx/exec`）。
6. 打開網站的 `index.html`，搜尋 `const CONFIG`，把網址貼進 `SCRIPT_URL` 的引號內：

   ```js
   SCRIPT_URL: "https://script.google.com/macros/s/xxxx/exec",
   ```

7. 完成！可先在瀏覽器直接打開該網址測試，看到「何必館表單後端運作中 ok」代表部署成功；
   再到網站上送出一筆測試預約，確認試算表出現新的一列、信箱收到通知。

## 注意

- 之後若修改 Code.gs，要再走一次 **部署 → 管理部署作業 → 編輯 → 版本選「新版本」→ 部署**，改動才會生效（網址不變）。
- 電話欄位前面加了 `'`，是為了避免 Google Sheet 把 0912… 開頭的 0 吃掉。

## 既有網站更新：預約表單 v3（2026-09-05）

這次需同時準備新版網站與新版 Apps Script，**只 push 網站不會更新 Google 後端**。
`BOOKING_SCHEMA_VERSION = 3` 是網站與後端的相容性版本，不是 Google 自動編號的部署版本。必須貼上整份新版 `Code.gs`，不能只把版本數字改為 3。

建議部署說明：`何必館預約 v3｜電話與過期場次檢核、通知容錯、重送去重`。

1. 開啟原本綁定預約試算表的 Apps Script 專案，不必另建試算表。
   - [原 Apps Script 編輯器](https://script.google.com/u/0/home/projects/1EA0gFS1aeaCUXaLmYHVWqKfudeMXG18HpYYLWBqjq9wQcrwI_CgO8K7J/edit)
   - [原預約試算表](https://docs.google.com/spreadsheets/d/1sn5YJBOCHNCcJUO5NZ6CoJdABScLgGhKk6XW44ATyD8/edit)
2. 將本資料夾的 `Code.gs` 全文貼回編輯器並儲存。保留正確的通知信箱與每時段容量設定。
3. **部署 → 管理部署作業 → 選原本網頁應用程式 → 編輯（鉛筆）→ 版本選「新版本」→ 部署**。執行身分維持「我」、存取權限維持「所有人」，原 `/exec` 網址不變。
4. 開啟[版本檢查網址](https://script.google.com/macros/s/AKfycbxdvzxrHNJjfR2l0t2lYuK2NEhKxjrN2UspiuK4Qs6GgJeTXEyhDBPa5J6HVRsO4v0O/exec?action=capabilities)，應看到 `{"bookingSchemaVersion":3}`。此檢查不會建立預約或寄信；只看到「何必館表單後端運作中 ok」不代表已更新到新版。
5. 同一更新時段完成新版網站的 push／Vercel 部署，再重新整理預約頁。前端版本檢查與後端不一致時會暫停送出，因此不要長時間只更新其中一邊。
6. 部署完成後，再由你送一筆有明確「測試」姓名、可接收聯絡的電話之預約，確認畫面顯示「預約資料已收到」，試算表有新的一列、LINE ID 正確、個資同意為「已同意」、通知狀態為「已寄送」，並確認收到屋主通知信。測試會占一組名額；確認後只刪除該筆測試列，再重新整理頁面釋放名額。不要刪掉欄名或其他真實預約。

- 姓名、電話、日期、時段不可空白，`privacyConsent` 必須為 `true`；前後端都會檢查。
- 電話接受台灣手機、市話與 `+國碼` 國際號碼，容許空白、括號及連字號；`abc` 等格式會被拒絕。這是格式檢核，不是電話或身分驗證。
- LINE ID 可留空；網站不再收集買方電子信箱，但寄給屋主的通知信仍正常寄送。
- 稱謂恢復為先生／小姐選填，不預選；沿用 v3 已支援的 `title`，寫入原第 3 欄並帶入屋主通知信。已部署 v3 者不需為此再更新 Apps Script。
- 原 Email 欄及歷史資料保留；新預約的該欄留空，通知內容不再列出買方 Email。
- 原前七欄位置不變；首次有效預約時會在最後補齊「LINE ID、個資同意、希望看屋時間、通知狀態、預約識別碼」。已有欄位不重複建立，既有其他欄位會保留，不需手動插入或移動欄位。
- 舊預約不會被補填「已同意」，避免誤造過去的同意紀錄。

### 場次維護與通知失敗

- 新增場次時，同步修改 `index.html` 的 `CONFIG.DATES` 與 `Code.gs` 的 `BOOKING_DATES`，再分別更新網站及原 Apps Script 部署。容量兩邊都維持 `SLOT_CAPACITY = 1`。
- 場次開始時間按台北時間 `+08:00` 判斷。前端載入、回到頁面與每分鐘更新選單，已開始的場次排除；當天所有場次開始後，該日期也排除。後端寫入前仍會重新檢查，避免舊頁面或修改裝置時間繞過。
- 「其他時間」不會過期，選取時才出現選填的「希望看屋時間」。收到後仍需人工聯繫確認，並非自動確定看屋。
- 只要預約已寫入，屋主通知信寄送失敗不會回傳「預約失敗」。試算表的「通知狀態」會標記失敗；如果狀態更新也失敗，可能停在「待寄送」。**沒有自動重寄**，請定期查看試算表，不要只依賴信箱。
- 同一頁面送出遇到網路中斷／無法讀取結果時，表單會保留原次請求，暫時鎖定欄位並提供「確認送出結果」。重試會核對相同識別碼，已存入則回覆成功，不再占位或寄信。請勿先重整或關閉分頁；識別碼只放在記憶體，重新開頁不保留。
- 送出成功畫面列出日期、時段及希望時間，告知後續會透過電話、簡訊或所填 LINE 聯繫。此畫面是收件確認，不是已確認帶看，也不會自動發送買方 Email／LINE 訊息。
